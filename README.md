# 听纹修复

打开页面获得内置三秒录音及一块污染选区。可导入自己的 WAV，在谱图拖选或用表单输入数值。添加选区后生成修复，切换原声与修复试听，再下载 PCM WAV。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm run build
npm start
```

浏览器访问 `http://127.0.0.1:4813`。可用 `PORT` 调整端口。前端由原生 HTML、CSS、JavaScript 构成。项目可离线运行，使用本机浏览器和 Node.js 标准库。

## 工作流

- 录音识别。保留声道数、采样率和帧数。
- 谱图计算。窗长变化使真实频格宽度变化。
- 频带衰减。污染选区附近频带能量下降。
- 旁路重建。无选区的输出逐帧等价。
- 量测和 PCM 输出。保持源帧数并给出逐声道差值。

可参阅 `PROJECT_SPEC.md` 了解输入、规则和接口。构建命令检查语法与服务装载。自动化测试套件留待后续。

## 平顶检查与补峰

访谈录音常有削平波峰，另一声道可能只有单个满幅瞬态。页面顶部的“平顶检查”工作台支持：

1. 拖圈或输入秒数圈出检查时段，可随时改查全段。
2. 按声道分组显示“可补的平顶”和“证据不足”，并把单个满幅样点单列为“满幅瞬态（非平顶）”。
3. 每条结果可“跳转试听”，勾选一个或多个整段作为修复对象。

领域规则（由 `server/repair/flattops.mjs` 统一实现，前后端共用）：

- 平顶是长度至少 2 的极大等幅高电平稳态段；单个满幅样点不算平顶。
- 圈线只要与某平顶的任意样点相交（含压在中段），就返回该平顶的完整 `startSample/endSample`；多个子区间选择映射到同一对象，同一平顶不会拆修。
- 起点或终点贴住文件边界、缺少任一侧有效样点的平顶标记为 `evidence` / `unresolved`，任何补峰请求都会跳过它。
- 只对选中的可补对象补峰：拱线接回两侧减半锚点，峰值严格超过原削平幅度（PCM16 可表示范围内）。
- 全段两路的所有未选样值统一 `Math.round(sample / 2)`（工作台舍入，半值朝 +∞）并写出 PCM16；未选样点只做这一步。
- 原声保留；试听与下载使用同一个 Base64 WAV，帧数/声道/时长与原声一致。

接口沿用 `/api/spectral-mend` 前缀：

- `POST /clips`（别名 `/scan`、`/flat-tops`、`/detect`）：接收 `{ wav, start?, end? }`，返回按声道的 `repairable`、`evidence`、`transients` 与波形桶。
- `POST /declip`（别名 `/render`、`/finish`、`/repair-clips`）：另收 `selections`（id、`{channel,startSample,endSample}` 或秒区间均可），返回等长 `wav`、逐对象 `results` 与逐声道 `metrics`。
- 旧 `POST /repair` 频谱选区契约保持不变：`regions: []` 仍逐字节旁路；仅当载荷是平顶选择形状时才分流到新管线。

`npm test` 运行 `test/` 下的规则测试。
