# 听纹修复

打开页面获得内置三秒录音：设备嗡声正在升频，与一条稳定的伴随音交会。先在原谱图上圈出嗡声的时频范围，再在交会前后各点一次嗡声，页面逐窗确认路线后才允许修复。也可导入自己的 WAV，或用原来的矩形选区直接衰减。修复后切换原声与修复对听，再下载 PCM WAV。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm run build
npm start
```

浏览器访问 `http://127.0.0.1:4813`。可用 `PORT` 调整端口。前端由原生 HTML、CSS、JavaScript 构成。项目可离线运行，使用本机浏览器和 Node.js 标准库。

## 咝声路线

- 圈定。在谱图拖选出嗡声经过的时频范围，或输入起止时间与频带。圈定以外一律保持原样。
- 定位。在交会前后各点一次嗡声（也可补点到 32 个）。每个定位点必须落在唯一可分的双峰上，否则拒绝修复并要求改点。
- 确认。逐窗判定：双峰须至少相隔四格频格并连续至少三个窗。合峰、缺声与归属不明处逐窗标为未确认并保留原样；其中能分出的双峰会在列表里给出可补点。
- 复核。每段稳定双峰取居中一窗核对：嗡声至少降 6 dB，伴随音变化小于 1 dB。未通过的片段同样退回未确认。
- 重确认。改点、补点、换录音、换窗或重圈都会作废上一条结果并重新分析。
- 衰减与接回。只衰减确认片段，边缘用余弦斜坡平滑接回原声，圈定时段外的采样逐字节保留。

## 工作流

- 录音识别。保留声道数、采样率和帧数。
- 谱图计算。窗长变化使真实频格宽度变化。
- 频带衰减。矩形选区附近频带能量下降。
- 嗡声路线修复。确认片段内的嗡声被衰减，未确认处保持原样。
- 旁路重建。无选区的输出逐帧等价。
- 量测和 PCM 输出。保持源帧数并给出逐声道差值；试听与下载共用同一份等长结果。

## 接口

- `POST /api/spectral-mend/inspect`：谱图。
- `POST /api/spectral-mend/trace`：`trace` 含 `range`、`points`、`db`，返回逐窗判定、确认片段、未确认清单与居中窗核对，不改变音频。
- `POST /api/spectral-mend/repair`：同上再加 `regions` 矩形选区，返回 PCM WAV、谱图、逐声道计量与 `trace` 报告。

可参阅 `PROJECT_SPEC.md` 了解输入、规则和接口。构建命令检查语法与服务装载。自动化测试套件留待后续。
